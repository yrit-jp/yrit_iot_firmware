# デバイス設定値リファレンス

本ドキュメントでは、YRIT IoT Firmware で使用されるマイコン内部の設定値について説明します。

## 📖概要

IoT デバイスプログラムでは、内部に不揮発性の設定ファイルを JSON 形式で保持しています。設定アプリケーションを利用することで、これらの内部設定をノーコードで変更することができます。

設定値は `defineSettingTemplate()` 関数によって共通設定とデバイス固有設定がマージされ、最終的な設定テンプレートが生成されます。

| 種類                 | 説明                         | 定義場所                                   |
| -------------------- | ---------------------------- | ------------------------------------------ |
| **共通設定**         | 全デバイス共通の設定項目     | `src/config/setting_parameters.cpp`        |
| **デバイス固有設定** | デバイスごとに異なる設定項目 | 各 `hal_*.cpp` の `deviceUniqueSettings()` |

---

## ⚙️ 共通設定

すべてのデバイスで使用可能な設定項目です。ただし、デバイスによってはサポートされない項目もあります。

### PARAM - 基本パラメータ

| キー              | デフォルト値 | 説明                                         |
| ----------------- | ------------ | -------------------------------------------- |
| `devID`           | `"99_99"`    | デバイス識別 ID（送信データに付与される）    |
| `WAIT_00_SEC`     | `"false"`    | 毎分 00 秒に送信タイミングを合わせるかどうか |
| `BATCH_DATA_SEND` | `"false"`    | データをバッチ送信（一括送信）するかどうか   |
| `TX_INTERVAL_SEC` | `"5"`        | データ送信間隔（秒）                         |

一部のデバイスでは、追加の PARAM 設定が定義されています。

| キー                 | デフォルト値 | 説明                                      |
| -------------------- | ------------ | ----------------------------------------- |
| `WAKE_BAT`           | `"false"`    | バッテリースリープ防止機能の有効化/無効化 |
| `LED_BRIGHTNESS_PCT` | `"10"`       | LED の明るさ（パーセント）の調整          |

### SAMPLING - サンプリング設定

| キー        | デフォルト値 | 説明                                      |
| ----------- | ------------ | ----------------------------------------- |
| `I2C_MS`    | `"3000"`     | I2C センサのサンプリング間隔（ミリ秒）    |
| `GPIO_MS`   | `"3000"`     | GPIO のサンプリング間隔（ミリ秒）         |
| `MODBUS_MS` | `"3000"`     | Modbus センサのサンプリング間隔（ミリ秒） |
| `CAMERA_MS` | `"100"`      | カメラのサンプリング間隔（ミリ秒）        |

> ⚠️ **注意**  
> 画面の更新頻度であり、データ送信頻度とは無関係です。
> データ送信間隔は `TX_INTERVAL_SEC` を参照してください。

### I2C_PORTx - I2C ポート設定

`I2C_PORT1` は全デバイス共通で自動的に定義されます（`commonSettingTemplate()`）。
複数の I2C ポートを持つデバイス（M5Stack Atom S3/S3R など）では、`I2C_PORT2` 以降がデバイス固有設定として追加されます。

| キー                | デフォルト値 | 説明                                                        |
| ------------------- | ------------ | ----------------------------------------------------------- |
| `IGNORE_ADDR_REGEX` | `""`         | 自動検出から除外する I2C スレーブアドレスの正規表現パターン |
| `IGNORE_NAME_REGEX` | `""`         | 自動検出から除外するセンサ名の正規表現パターン              |

> ⚠️ **注意**  
> パターンは `|`（パイプ）区切りで複数指定できます（例: `0x76|0x77`）。パイプをリテラル文字として使いたい場合は `\|` でエスケープしてください。
> アドレス側は各アドレスを `0xXX`（16進）と `XX`（10進）の両方の文字列表現に変換した上で、パターンと完全一致するかどうかで判定します（部分一致では除外されません）。

**設定例**（I2C_PORT1 で、アドレス `0x76`・`0x77` と、センサ名に '\_Temp\_' が含まれるセンサを検出対象から除外する場合）:

```json
{
  "I2C_PORT1": {
    "IGNORE_ADDR_REGEX": "0x76|0x77",
    "IGNORE_NAME_REGEX": ".*_Temp_.*"
  }
}
```

> 完全一致判定のため、名前の一部だけを除外したい場合は `.*_Temp_.*` のようにワイルドカード（`.*`）を組み合わせる必要があります（`_Temp_` だけでは、センサ名が完全に `_Temp_` と一致する場合しか除外されません）。

### WIFI - Wi-Fi 設定

| キー                 | デフォルト値    | 説明                                                                      |
| -------------------- | --------------- | ------------------------------------------------------------------------- |
| `SSID`               | `""`            | 接続先 Wi-Fi の SSID                                                      |
| `PASS`               | `""`            | 接続先 Wi-Fi のパスワード                                                 |
| `NTP_SERVER`         | `"ntp.nict.jp"` | 時刻同期に使用する NTP サーバーのホスト名（タイムゾーン: 日本時間 JST-9） |
| `STATIC_IP`          | `""`            | 固定 IP アドレス                                                          |
| `STATIC_GATEWAY`     | `""`            | 固定ゲートウェイアドレス                                                  |
| `STATIC_SUBNET_MASK` | `""`            | 固定サブネットマスク                                                      |
| `DNS`                | `""`            | DNS サーバーアドレス                                                      |

> **❗ 固定 IP を使用する場合**  
> 固定 IP アドレスを使用するには、`STATIC_IP`、`STATIC_GATEWAY`、`STATIC_SUBNET_MASK`、`DNS` の全ての項目を設定してください。
> いずれかが空の場合は DHCP（自動割り当て）が使用されます。

<br/>

> **❗ 固定 IP を使用する場合**

### LORA_WAN - LoRaWAN 送信設定

| キー            | デフォルト値                         | 説明                                                                         |
| --------------- | ------------------------------------ | ---------------------------------------------------------------------------- |
| `ENABLE`        | `"false"`                            | LoRaWAN 送信を有効にするかどうか                                             |
| `ABP`           | `"false"`                            | `"true"` の場合 ABP で接続、`"false"` の場合 OTAA で接続（対応デバイスのみ） |
| `OTAA_DEV_EUI`  | チップ固有 MAC アドレスから自動生成  | OTAA 接続時のデバイス EUI（EUI-64形式）                                      |
| `OTAA_JOIN_EUI` | `"0000000000000000"`                 | OTAA 接続時の Join EUI / App EUI                                             |
| `OTAA_APP_KEY`  | チップ固有 MAC アドレスから自動生成  | OTAA 接続時のアプリケーションキー                                            |
| `ABP_DEV_ADDR`  | `"00000000"`                         | ABP 接続時のデバイスアドレス（対応デバイスのみ）                             |
| `ABP_NWK_S_KEY` | `"00000000000000000000000000000000"` | ABP 接続時のネットワークセッションキー（対応デバイスのみ）                   |
| `ABP_APP_S_KEY` | `"00000000000000000000000000000000"` | ABP 接続時のアプリケーションセッションキー （対応デバイスのみ）              |
| `FPORT_NAME`    | `9`                                  | センサ名送信用 FPort（1〜223、`199` は使用不可）                             |
| `FPORT_VALUE`   | `10`                                 | センサ値送信用 FPort（1〜223、`199` は使用不可）                             |

> ⚠️ **注意**  
> `FPORT_NAME`/`FPORT_VALUE` に `199` を指定すると初期化に失敗します（WM1110 モジュールがメトリクス収集用に予約しているため）。
> `OTAA_DEV_EUI`（EUI-64）と `OTAA_APP_KEY` は、チップの eFuse MAC アドレス（6byte）から算出されますが、いずれもセキュリティが必要な用途では別途ユーザー側で上書き設定してください。

## 🎛️ デバイス固有設定

デバイスごとに定義される設定項目です。各 HAL ファイルの `deviceUniqueSettings()` 関数で定義されています。

### MODBUS_x - Modbus ポート設定

Modbus ポートを持つデバイスで使用可能です。`x` はポート番号（1, 2 など）を示します。
キー名は `HAL.Modbus.getModifier()`（すべてのデバイスで固定値 `"MODBUS"`）+ ポート番号で構成され、**アンダースコアなし・1始まり**で `MODBUS1`、`MODBUS2` のようになります。

> ⚠️ **注意**  
> `MODBUS_0`/`MODBUS_1`（アンダースコア区切り、0始まり）ではありません。実際のキーは `MODBUS1`/`MODBUS2`（1始まり）です。

| キー         | デフォルト値 | 説明                                 |
| ------------ | ------------ | ------------------------------------ |
| `BAUDRATE`   | `"9600"`     | ボーレート（bps）                    |
| `DATA_BIT`   | `"8"`        | データビット長                       |
| `PARITY`     | `"0"`        | パリティ（0: None, 1: Even, 2: Odd） |
| `TIMEOUT_MS` | `"200"`      | 通信タイムアウト（ミリ秒）           |
| `ID_MIN`     | `"1"`        | スキャンするユニット ID の最小値     |
| `ID_MAX`     | `"5"`        | スキャンするユニット ID の最大値     |

> ⚠️ **注意**  
> ストップビットは 1 で固定されており、変更できません。

### GPIO_x - GPIO ピン設定

GPIO ピンを持つデバイスで使用可能です。`x` はピン番号を示します。
キー名は `HAL.Gpio.getModifier()` + ピン番号で構成されますが、**接頭辞（modifier）はデバイスによって異なり、"GPIO_" ではありません**。

| デバイス                                        | modifier | キー例（GPIO26 の場合） |
| ------------------------------------------------ | :------: | :---------------------: |
| M5Stack シリーズ、Arduino Nesso N1               |   `G`    |          `G26`          |
| ESP32 DevKit                                     |   `P`    |          `P26`          |
| Wio Terminal、Wio Tracker 1110                   |   `IO`   |         `IO26`          |

> ⚠️ **注意**  
> `GPIO_25`/`GPIO_26` ではありません。実際のキーはデバイスごとの modifier（`G`/`P`/`IO`）+ ピン番号です（アンダースコアなし）。

#### デジタル入力ピン

| キー               | デフォルト値 | 説明                                                                |
| ------------------ | ------------ | ------------------------------------------------------------------- |
| `ENABLE`           | `"false"`    | このピンを有効にするかどうか                                        |
| `NAME`             | `"GXX"`      | ピンの識別名（送信データに付与される）                              |
| `TX_ON_CHANGE`     | `"false"`    | 値変化時に即時送信するかどうか<br/>（サンプリング間隔に依存します） |
| `TX_LINK_I2C`      | `"false"`    | GPIO の変化に連動して I2C データを送信するかどうか                  |
| `TX_LINK_MODBUS`   | `"false"`    | GPIO の変化に連動して Modbus データを送信するかどうか               |
| `PULL_UP`          | `"false"`    | 内部プルアップを有効にするかどうか                                  |
| `PULSE_COUNT_RISE` | `"false"`    | 立ち上がりエッジでパルスカウントするかどうか                        |
| `PULSE_COUNT_FALL` | `"false"`    | 立ち下がりエッジでパルスカウントするかどうか                        |

#### アナログ入力ピン（ADC 対応ピン）

上記に加えて、以下の設定が追加されます。

| キー          | デフォルト値 | 説明                                                                                                       |
| ------------- | ------------ | ---------------------------------------------------------------------------------------------------------- |
| `SHIFT_LEVEL` | `"4"`        | ADC 値のビットシフト量（ノイズ低減用）。<br/>値の粒度を調整し、`TX_ON_CHANGE` の変化検出感度に影響します。 |
| `DIGITAL`     | `"false"`    | デジタル入力として扱うかどうか（`"true"` でデジタル入力、`"false"` でアナログ入力）                        |

### CAMERA - カメラ設定

カメラを搭載しているデバイス（M5Stack CoreS3 など）で使用可能です。

| キー     | デフォルト値 | 説明                       |
| -------- | ------------ | -------------------------- |
| `ENABLE` | `"false"`    | カメラを有効にするかどうか |

## 📝 設定ファイルの例

以下は、設定ファイル（JSON）の例です。

```json
{
  "PARAM": {
    "devID": "01_01",
    "WAIT_00_SEC": "false",
    "BATCH_DATA_SEND": "false",
    "TX_INTERVAL_SEC": "60"
  },
  "SAMPLING": {
    "I2C_MS": "3000",
    "GPIO_MS": "3000",
    "MODBUS_MS": "3000"
  },
  "WIFI": {
    "SSID": "MyNetwork",
    "PASS": "MyPassword",
    "NTP_SERVER": "ntp.nict.jp",
    "STATIC_IP": "",
    "STATIC_GATEWAY": "",
    "STATIC_SUBNET_MASK": "",
    "DNS": ""
  },
  "MQTT": {
    "ENABLE": "true",
    "BROKER": "mqtt.example.com",
    "PORT": "1883",
    "USER": "",
    "PASS": "",
    "BASE_TOPIC": "sensors/device01",
    "RETAIN": "false"
  },
  "I2C_PORT1": {
    "IGNORE_ADDR_REGEX": "",
    "IGNORE_NAME_REGEX": ""
  },
  "MODBUS1": {
    "BAUDRATE": "9600",
    "DATA_BIT": "8",
    "PARITY": "0",
    "TIMEOUT_MS": "200",
    "ID_MIN": "1",
    "ID_MAX": "10"
  },
  "G26": {
    "ENABLE": "true",
    "NAME": "SW1",
    "TX_ON_CHANGE": "true",
    "TX_LINK_I2C": "false",
    "TX_LINK_MODBUS": "false",
    "PULL_UP": "true",
    "PULSE_COUNT_RISE": "false",
    "PULSE_COUNT_FALL": "false"
  }
}
```

> ⚠️ **注意**  
> `MODBUS1`/`G26` のキー名はデバイスに依存します（[MODBUS_x](#modbus_x---modbus-ポート設定)・[GPIO_x](#gpio_x---gpio-ピン設定)セクション参照）。上記は M5Stack 系デバイス（modifier `G`）を例にしています。
